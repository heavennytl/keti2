# 《工业模型适配与协同运行系统》PRD（Demo版 v3.0）

> 基于 v2.0 的深度优化迭代
> 核心目标：解决"适配方案不够智能、页面间数据割裂、交互深度不足"三大问题，让评审者真正感受到"AI驱动的智能适配"能力

---

## 1. 迭代背景

### 1.1 v2.0 的成果

v2.0 成功打通了"适配→部署→运行→优化"的完整故事线，实现了页面间 URL 参数传递联动，以及一键适配/部署/调度的动画效果。

### 1.2 v2.0 的遗留问题

经过全面审查，v2.0 存在以下突出问题：

| 问题分类 | 问题 | 严重程度 | 影响 |
|----------|------|----------|------|
| **适配智能性** | 适配方案推荐是硬编码静态数据，无智能推荐感 | P0 | 核心价值被削弱 |
| **数据割裂** | 适配器市场与适配流程脱节，无数据联动 | P0 | 体验不连贯 |
| **模板复用浅** | 模板只是静态展示，无参数继承/覆盖机制 | P1 | 复用价值未体现 |
| **缺少ROI展示** | 没有适配成本/周期缩短的量化对比 | P1 | 企业用户无感知 |
| **兼容性矩阵未实现** | PRDv1 设计的兼容性矩阵在代码中缺失 | P1 | 功能不完整 |
| **推理链编排未实现** | PipelineEditor 只有表格，无拖拽画布 | P0 | 核心功能缺失 |
| **驾驶舱图表缺失** | Dashboard 无 ECharts 性能图表 | P1 | 数据展示不充分 |
| **场景联动不完整** | 场景切换只影响 Monitor/Dashboard，其他页面无联动 | P1 | 全局体验不一致 |
| **状态处理缺失** | 多数页面缺少加载态/空态/错误态处理 | P2 | 体验粗糙 |
| **MSW 未使用** | 所有数据都是硬编码，MSW Mock 层未实际使用 | P2 | 架构设计未落地 |
| **页面交互单一** | 大部分页面只有表格展示，缺乏动态交互 | P1 | 评审体验差 |
| **模型仓库与适配脱节** | ModelRepo 的适配状态与 ModelAdapt 无联动 | P1 | 数据孤岛 |

### 1.3 v3.0 的优化方向

| 优化方向 | 具体措施 | 预期效果 |
|----------|----------|----------|
| **智能适配升级** | 多候选方案对比、基于历史数据的推荐、适配器选择影响评分 | 评审者感受到"AI驱动"而非"静态展示" |
| **数据打通** | 适配器市场↔适配流程联动、模型仓库↔适配中心联动、兼容性矩阵实现 | 页面间数据真正流动 |
| **补齐缺失功能** | 推理链拖拽画布、驾驶舱 ECharts 图表、兼容性矩阵热力图 | 功能完整度提升 |
| **增强交互深度** | 所有页面增加加载/空/错误态、动态数据刷新、交互反馈 | 体验专业度提升 |
| **ROI 量化展示** | 适配成本对比、周期缩短趋势、累计节省成本 | 企业用户有感知 |
| **场景全局联动** | 场景切换影响所有页面数据 | 全局体验一致 |

```
Step 3: 预览适配方案

  ├─ 与原始模板的差异对比
  └─ 预估成功率和周期

  └─ 创建适配任务并开始执行
```

## 3. 全局增强功能

### 3.1 场景全局联动

**现状问题：** 场景切换只影响 Monitor 和 Dashboard，其他页面无联动。

**改造方案：**

| 页面 | 场景联动内容 |
|------|-------------|
| 驾驶舱 | 节点状态、指标数据、适配健康度 |
| 适配中心 | 适配质量评分、适配成功率 |
| 部署中心 | 部署状态、运行实例数 |
| 推理引擎 | 引擎负载、推理性能 |
| 推理链编排 | 推理链运行状态 |
| 运行监测 | 告警数据、节点指标 |
| 资源调度 | 节点负载、调度事件 |
| 模型仓库 | 模型运行状态 |
| 节点管理 | 节点状态、兼容性数据 |

### 3.2 页面状态处理

**现状问题：** 多数页面缺少加载态/空态/错误态处理。

**改造方案：**

所有页面统一实现以下状态：

| 状态 | 实现方式 | 触发条件 |
|------|----------|----------|
| 加载态 | Ant Design Skeleton 骨架屏 | 数据加载中 |
| 空态 | EmptyState 组件 + 引导文案 | 无数据时 |
| 错误态 | ErrorState 组件 + 重试按钮 | 数据加载失败 |
| 边界态 | 分页/虚拟滚动/缩略图导航 | 大量数据时 |

### 3.3 数据流动与状态保持

#### 3.3.1 全局数据状态管理

使用 Zustand 实现全局数据状态管理：

```
useSceneStore (全局场景)
     │
     ├── useModelAdaptStore    ← 适配数据（增强）
```

## 7. 风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| AntV X6 画布实现复杂 | 推理链编排开发周期长 | 先实现基础拖拽和连线，高级功能后续迭代 |
